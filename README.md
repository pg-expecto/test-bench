# test-bench
Тестовый стенд на виртуальной машине для тестирования сценариев и гипотез

# Виртуальная среда
VirtualBox

# Дистрибутив Linux 
Debian

---

# Общий структурный план реализации задачи, разбитый на этапы. План описывает последовательность действий и ключевые результаты каждого шага без привязки к конкретным командам, файлам или настройкам.

### 1. Подготовка Ansible роли (базовая структура)
- Создать каталог роли с типовым набором подкаталогов (`tasks`, `handlers`, `templates`, `files`, `vars`, `defaults`, `meta`).
- Определить назначение роли и основные задачи (task-файлы).
- Подготовить шаблоны и статические файлы, если они требуются.
- Задать переменные по умолчанию и обязательные переменные.
- Описать метаданные роли (зависимости, поддерживаемые платформы).
- **Результат:** готовая к использованию структура роли, соответствующая стандартам Ansible.

### 2. Тестовый прогон роли без выполнения
- Проверить синтаксис YAML-файлов и структуру роли с помощью встроенных средств Ansible (например, `--syntax-check`) и/или линтеров.
- Выполнить прогон в режиме проверки (`--check`), чтобы убедиться в отсутствии ошибок в логике и путях, без фактического изменения целевых систем.
- Проверить корректность ссылок на файлы, шаблоны и переменные.
- **Результат:** подтверждённая работоспособность структуры и синтаксиса роли, отсутствие очевидных ошибок.

### 3. Загрузка файлов роли в проект GitLab
- Инициализировать локальный Git-репозиторий (если ещё не создан) и добавить файлы роли.
- Сделать коммит с осмысленным сообщением.
- Настроить удалённый репозиторий GitLab и отправить изменения (push).
- Убедиться, что структура роли корректно отображается в веб-интерфейсе GitLab.
- **Результат:** роль размещена в GitLab и доступна для дальнейшего использования в AWX.

### 4. Подготовка inventory, credential, templates, jobs для AWX
- В AWX создать инвентарь (inventory) с целевыми хостами или группами хостов.
- Добавить учётные данные (credential) для доступа к целевым хостам (SSH-ключи, пароли и т.п.).
- Настроить шаблон (template) задания: указать репозиторий GitLab, ветку, путь к playbook, инвентарь и учётные данные.
- При необходимости создать расписание (schedule) или настроить уведомления.
- **Результат:** в AWX создано окружение, готовое к запуску playbook с ролью.

### 5. Выполнение Ansible playbook с помощью AWX
- Запустить созданный шаблон (template) задания в AWX.
- Отслеживать статус выполнения задания, просматривать логи и вывод.
- Убедиться в успешном применении роли на целевых хостах.
- При необходимости скорректировать inventory, credential или шаблон и повторить запуск.
- **Результат:** playbook успешно выполнен через AWX, роль применена к целевым системам.
